## Certificate investigation

PR #346 added `check_python_trust.py` and `check-node-trust.cjs` as repository
preflight checks after the emSign incident. They are custom checks, distinct
from TLS certificate verification. They reject compromised G3 roots and old
installer versions; deleting a preflight would not repair the underlying
trust store. Package installation is a relevant exposure because intercepted
package bytes can become executed code. This investigation found no evidence
that interception occurred.

The laptop's effective Python/Homebrew CA bundle has 183 roots with G3 absent;
application certifi 2026.10.19 has 120 roots with G3 absent. Base pip is 26.2.2,
uv is 0.13.5, and Node 22.23.4's bundled/effective stores have 116 roots with G3
absent. No certificate bypass was needed. The cloud's actual image and failed
command were not available in this local task, so its exact failing trust
surface is not independently confirmed here.

Fresh [Python incident guidance](https://discuss.python.org/t/information-for-python-users-regarding-emudhra-emsign-ca-certificate-security-incident/109576)
now also recommends uv 0.13.6 and patched Python releases (including 3.11.18)
for expanded protection. It clarifies that uv did not bundle the compromised
root; its newer recommendation also enables updated managed Python releases.
The repository's older uv floor is therefore not a complete statement of the
latest guidance. This task did not update global runtimes, provider-owned cloud
images, or security policy. Safe cloud alternatives are a provider-refreshed
image or approved updated tooling and a verified CA bundle, preserving required
enterprise roots and HTTPS verification.
